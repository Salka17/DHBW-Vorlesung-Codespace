## Von der Aufgabe zum Programm

Ein Programm führt konkrete Anweisungen aus, etwa für Berechnungen oder zur Automatisierung.

**Beispiel: Alter in Tagen berechnen**

1. Alter in Jahren entgegennehmen
2. Mit 365 multiplizieren
3. Ergebnis in Tagen anzeigen

**Eingabe → Verarbeitung → Ausgabe**

Eine genaue Schrittfolge zur Lösung einer Aufgabe heißt **Algorithmus**.

Note:
- Ein alltagsnahes Beispiel sammeln lassen, etwa wiederkehrende Rechnungen.
- Der Computer errät unsere Absicht nicht. Wir müssen Daten und Schritte genau beschreiben.
- Die Schritte sind eine Beschreibung in Alltagssprache, noch kein C#.
- Gemeinsam für 20 Jahre durchspielen: 20 × 365 = 7300.
- Die Rechnung ist eine Näherung: Schaltjahre und das genaue Geburtsdatum bleiben hier unberücksichtigt.

## Erstes C#-Programm

```csharp
Console.WriteLine("Hallo!");
Console.WriteLine("Programmierung mit C#.");
```

Ausgabe:

```text
Hallo!
Programmierung mit C#.
```

Anweisungen werden hier **von oben nach unten** ausgeführt.

Note:
- Code und Ausgabe klar unterscheiden: Quelltext schreiben wir, die Ausgabe erzeugt das Programm.
- Zeilen einzeln zeigen und die erwartete Ausgabe abfragen.
- C# ist die Programmiersprache. Die Konsole ist der Bereich für Textausgaben und Texteingaben.

---

## Aufbau einer Anweisung

```csharp
Console.WriteLine("Hallo!");
```

| Bestandteil | Bedeutung |
|---|---|
| `Console.WriteLine` | Text oder einen Wert mit Zeilenumbruch ausgeben |
| `(...)` | Enthält den auszugebenden Text oder Wert |
| `"Hallo!"` | Ein Textwert; die Anführungszeichen begrenzen den Text |
| `;` | Beendet die Anweisung |

Note:
- WriteLine ist eine Methode, die wir aufrufen. Ihre innere Umsetzung müssen wir noch nicht kennen.
- Klammern und Anführungszeichen sind unterschiedliche Zeichen mit unterschiedlichen Aufgaben.
- Die Anführungszeichen und das Semikolon erscheinen nicht in der Ausgabe.
- Nicht behaupten, jede C#-Zeile brauche ein Semikolon: Später kommen Blöcke mit geschweiften Klammern.

## Zweck von Variablen

```csharp
Console.WriteLine(20);
Console.WriteLine(20 * 365);
```

Die Zahl `20` steht hier für ein Alter. Bei einer Änderung müssen beide Vorkommen angepasst werden.

Eine Variable speichert einen Wert unter einem **Namen**, über den er wiederverwendet werden kann.

Note:
- Problem zuerst besprechen: Die Bedeutung der Zahl steht nicht im Code, und sie ist doppelt eingetragen.
- Variablen ermöglichen, Werte einmal bereitzustellen und in mehreren Anweisungen zu verwenden.
- Die nächste Folie ersetzt beide Vorkommen durch einen Namen.

## Variablen: Typ, Name und Wert

```csharp
int alter = 20;
Console.WriteLine(alter);
```

| Bestandteil | Bedeutung |
|---|---|
| `int` | Datentyp: eine ganze Zahl |
| `alter` | Name des Speicherplatzes |
| `=` | Wert zuweisen |
| `20` | Startwert |
| `;` | Ende der Anweisung |

**Deklarieren:** Variable anlegen. **Initialisieren:** ersten Wert zuweisen.

Note:
- Bild eines beschrifteten Speicherfachs verwenden: Name auf dem Fach, aktueller Wert darin, Typ legt erlaubte Werte fest.
- Dies ist ein vereinfachtes Modell für die heute verwendeten lokalen Variablen. Keine Speicheradressen, Stack/Heap oder Referenzsemantik einführen.
- int steht für ganze Zahlen, etwa 0, 20 oder -3.
- Die Variable selbst wird nicht ausgegeben; WriteLine liest ihren aktuellen Wert.
- Diese Anweisung verbindet Deklaration und Initialisierung.
- Grundform mündlich wiederholen: Typ Name gleich Wert Semikolon.
- Wir geben Variablen heute direkt beim Anlegen einen Startwert.

```csharp
int alter = 20;

Console.WriteLine(alter);
Console.WriteLine("alter");
Console.WriteLine(20);
```

Ausgabe:

```text

20
```

`alter` liest die Variable. `"alter"` ist ein wörtlicher Text. `20` ist eine Zahl.

Note:
- Erst vorhersagen lassen. Dies ist eine zentrale Unterscheidung für Anfänger.
- Ein direkt im Code geschriebener Wert wie 20 oder "alter" heißt Literal.
- Ohne Anführungszeichen sucht C# hier eine Variable mit diesem Namen.

## Datentypen im Überblick

| Typ | Vorzeichen | Größe | Wertebereich / Inhalt |
|---|---|---|---|
| `byte` | Nein | 8 Bit | 0 … 255 |
| `short` | Ja | 16 Bit | −2¹⁵ … 2¹⁵ − 1 |
| `int` | Ja | 32 Bit | −2³¹ … 2³¹ − 1 |
| `long` | Ja | 64 Bit | −2⁶³ … 2⁶³ − 1 |
| `char` | — | 16 Bit | Eine UTF-16-Codeeinheit, z. B. `'A'` |
| `float` | Ja | 32 Bit | Bis ca. ±3,4 × 10³⁸; ca. 6–9 gültige Ziffern |
| `double` | Ja | 64 Bit | Bis ca. ±1,8 × 10³⁰⁸; ca. 15–17 gültige Ziffern |
| `decimal` | Ja | 128 Bit | Bis ca. ±7,9 × 10²⁸; ca. 28–29 gültige Ziffern |
| `bool` | — | 8 Bit | `true` oder `false` |
| `string` | — | Variabel | Text, z. B. `"Inhalt"` |

Note:
- Die vollständige ursprüngliche Tabelle wieder aufgreifen; string und decimal ergänzen, weil Text bereits verwendet wird und Dezimalwerte eingeordnet werden sollen.
- Zeilen direkt erklären: byte/short/int/long speichern ganze Zahlen mit unterschiedlichen Grenzen. Vorzeichen bedeutet, dass auch negative Zahlen möglich sind; byte ist vorzeichenlos.
- 8 Bit sind ein Byte. Mit mehr Bits lassen sich mehr unterschiedliche Werte darstellen. Die Grenzen dienen als Nachschlageinformation, nicht als Auswendiglernziel. int reicht von −2 147 483 648 bis 2 147 483 647.
- char speichert eine UTF-16-Codeeinheit; ein sichtbares Unicode-Zeichen kann mehr als eine solche Einheit benötigen. Für Texte string verwenden. string hat keine feste Gesamtgröße.
- float und double sind binäre Gleitkommazahlen: großer Bereich, aber begrenzte Genauigkeit. 6–9 bzw. 15–17 meint signifikante Ziffern, nicht feste Nachkommastellen. Die genannten Grenzen sind Näherungen für endliche Werte.
- decimal eignet sich für Dezimalrechnungen wie Geldbeträge; auch hier bestehen Grenzen und Rundungsmöglichkeiten. Die Einführung arbeitet überwiegend mit int und double.
- bool hat nur zwei logische Werte, auch wenn sizeof(bool) ein Byte ergibt. Größen beschreiben Werte, nicht den gesamten Verwaltungsaufwand einer Variable.
- Weitere Ganzzahlvarianten: sbyte (−128 … 127), ushort (0 … 2¹⁶−1), uint (0 … 2³²−1), ulong (0 … 2⁶⁴−1). Bei den u-Varianten entfällt das Vorzeichen. Nur kurz einordnen.
- Referenzen: [Ganzzahltypen](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/builtin-types/integral-numeric-types), [Gleitkomma- und Dezimaltypen](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/builtin-types/floating-point-numeric-types), [sizeof](https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/operators/sizeof).

## Datentypen definieren

Die Schreibweise eines direkt angegebenen Werts (**Literal**) bestimmt seinen Typ — auch ohne eine Variablendeklaration:

- `"Inhalt"` → `string`: Text in doppelten Anführungszeichen
- `'a'` → `char`: eine UTF-16-Codeeinheit in einfachen Anführungszeichen
- `123` → `int`: eine ganze Zahl ohne Dezimalpunkt
- `123.45` → `double`: eine Zahl mit Dezimalpunkt
- `true` / `false` → `bool`: Wahrheitswerte ohne Anführungszeichen

Im C#-Code ist das Dezimaltrennzeichen immer ein **Punkt**.

Note:
- Die Literale einzeln mit der Tabelle verbinden. Ein Typ muss nicht erst durch eine Variablendeklaration entstehen: Auch Console.WriteLine(123) erhält einen int-Wert.
- Bei var wird der Variablentyp aus dem Startwert abgeleitet. Das Schlüsselwort hier nur einordnen; eine eigene optionale Folie folgt später.
- Ein explizit deklarierter Zieltyp kann zulässige Umwandlungen erlauben, etwa double wert = 123;. Das int-Literal wird dann in double umgewandelt.
- Sehr große Ganzzahlliterale können ohne Suffix einen anderen Ganzzahltyp erhalten; für unsere kleinen Werte ist int die Standardwahl.
- Ein char-Literal enthält genau eine UTF-16-Codeeinheit. Einfache Beispiele wie 'a' verwenden.
- Die Ausgabe kann abhängig von der Kultur ein Komma verwenden. 1_000_000 ist eine lesbare Schreibweise derselben Zahl wie 1000000.

---

## Spezifische Datentypen definieren

Ein **Suffix** legt den Typ eines Zahlenliterals gezielt fest:

| Literal | Typ | Beispiel einer Deklaration |
|---|---|---|
| `123L` | `long` | `long anzahl = 123L;` |
| `123.45F` | `float` | `float temperatur = 123.45F;` |
| `123.45D` | `double` | `double laenge = 123.45D;` |
| `123.45M` | `decimal` | `decimal betrag = 123.45M;` |

Ohne Suffix hat `123.45` bereits den Typ `double`.

Note:
- L/l, F/f, D/d und M/m sind möglich. Große Buchstaben verwenden; ein kleines l ist leicht mit 1 zu verwechseln.
- float temperatur = 36.6F; funktioniert, float temperatur = 36.6; nicht: Das Literal ohne Suffix ist ein double und wird nicht automatisch in float umgewandelt.
- L legt den Literaltyp fest, erweitert aber nicht beliebig den Wertebereich.
- M für decimal ergänzt die wiederhergestellten Suffixe L/F/D.

## Typbindung und Zuweisungen

```csharp
int anzahl = 3;

```

Diese Zuweisungen passen nicht zu `int`:

```csharp
anzahl = "vier";     // Text statt Zahl
```

Der **Compiler** prüft den Code vor der Ausführung und meldet solche Fehler.

Note:
- Das zweite Codefeld ist absichtlich ungültig und kein zusätzliches vollständiges Programm.
- Compiler kurz als Übersetzer mit Prüfungen erklären, keine IL/JIT-Details.
- Einmal einen Typfehler live erzeugen, Fehlermeldung lesen und anschließend korrigieren.

## Rechenoperatoren

| Operator | Bedeutung | Beispiel | Ergebnis |
|---|---|---|---|
| `+` | Addition | `10 + 3` | `13` |
| `-` | Subtraktion | `10 - 3` | `7` |
| `*` | Multiplikation | `10 * 3` | `30` |
| `/` | Division | `10 / 3` | `3` |
| `%` | Rest bei Ganzzahldivision | `10 % 3` | `1` |

Multiplikation und Division werden vor Addition und Subtraktion ausgewertet. Klammern legen die Reihenfolge fest: `(2 + 3) * 4` ergibt `20`.

Note:
- Bei / die nächste Folie direkt anschließen: Das Ergebnis hängt von den Typen der beteiligten Werte ab.
- % am Beispiel erklären: 10 enthält dreimal die 3; 1 bleibt übrig.
- Rest später für die Gerade/Ungerade-Aufgabe wieder aufgreifen.

## Ganzzahl- und Gleitkommadivision

```csharp
Console.WriteLine(5 / 2);      // 2
Console.WriteLine(5.0 / 2);    // 2.5 oder 2,5 in der Ausgabe
```

- Zwei `int`-Werte: Der Nachkommateil wird abgeschnitten.
- Mit einem `double`-Wert: Das Ergebnis kann Nachkommastellen haben.

```csharp
double ergebnis = 5 / 2;      // Speichert 2, nicht 2.5
```

Note:
- Der Typ links verändert die bereits rechts ausgeführte Ganzzahldivision nicht.

## Bedingungen und Programmablauf

Die bisherigen Beispiele führen alle Anweisungen der Reihe nach aus.
`if` (**wenn**) und `else` (**sonst**) ermöglichen einen bedingten Ablauf.

```text
                 Alter mindestens 18?
                    /           \
               wahr             falsch
                ↓                  ↓
        „Volljährig“       „Minderjährig“
                \                  /
                 → Weiter im Programm
```

Die Bedingung ergibt einen `bool`-Wert: `true` oder `false`.
Pro Durchlauf wird **genau einer** der beiden Zweige ausgeführt.

Note:
- Zuerst ohne Code mit 20 und 16 Jahren durchgehen. Eine Entscheidung prüft den aktuellen Wert, sie wartet nicht darauf, dass die Bedingung irgendwann wahr wird.

## Syntax von `if` und `else`

```csharp [2|3-5|6-9|10]
int alter = 20;
if (alter >= 18)
{
    Console.WriteLine("Volljährig");
}
else
{
    Console.WriteLine("Minderjährig");
}
Console.WriteLine("Prüfung beendet.");
```

Note:
- Mit Weiter die Syntaxteile markieren: Bedingung, if-Block, else-Block, gemeinsame Fortsetzung. Die Highlights erklären den Aufbau, nicht die Ausführungsreihenfolge eines einzelnen Durchlaufs.
- Runde Klammern enthalten eine bool-Bedingung. Geschweifte Klammern begrenzen jeweils den zugehörigen Block und müssen paarweise gesetzt werden.
- Bei true läuft der if-Block, bei false der else-Block. Die letzte Ausgabe folgt in beiden Fällen.
- Die nächste Folie enthält die Erläuterungen als Nachschlagefolie.

---

## `if` und `else`: Bestandteile

- `if (...)`: Die runden Klammern enthalten die Bedingung.
- `{ ... }`: Ein Block fasst die zugehörigen Anweisungen zusammen.
- Der `if`-Block wird ausgeführt, wenn die Bedingung `true` ergibt.
- Der `else`-Block wird ausgeführt, wenn die Bedingung `false` ergibt.
- Nach dem gewählten Block geht es mit der gemeinsamen Fortsetzung weiter.

Note:
- Die Erklärungen können bereits auf der Codefolie mündlich gegeben werden. Diese Folie dient zum Nachlesen und kann beim Vortrag zügig weitergeschaltet werden.
- Bei alter=20 wird Volljährig ausgegeben, bei alter=16 Minderjährig. Prüfung beendet. folgt in beiden Fällen.

## Klammern, Einrückung und Semikolon

```csharp
int alter = 20;
if (alter >= 18)
{
    Console.WriteLine("Volljährig");
    Console.WriteLine("Erwachsenentarif");
}
Console.WriteLine("Diese Ausgabe folgt immer.");
```

- **Kein `;` direkt nach `if (...)` oder `else`.**
- Die Anweisungen **im Block** enden hier jeweils mit `;`.
- Einrückung macht den Block lesbar; die `{ }` legen ihn fest.
- `else` ist optional: Bei `false` wird der `if`-Block übersprungen.

Note:
- Mit alter=16 beide Ausgaben im Block überspringen und die letzte ausführen. if (...) mit anschließendem Semikolon hätte einen leeren Anweisungskörper und wäre ein typischer Logikfehler.
- Wir verwenden auch bei einer einzelnen Anweisung immer geschweifte Klammern.
- In einem Block deklarierte lokale Variablen gelten nur in diesem Block und seinen inneren Blöcken. Benötigt man eine Variable nach if/else, legt man sie vorher an.

## Logische Operatoren: Bedingungen verknüpfen

| Operator | Bedeutung | Beispiel |
|---|---|---|
| `&&` | Und: beide wahr | `(alter >= 18) && hatTicket` |
| `\|\|` | Oder: mindestens eine wahr | `hatTicket \|\| stehtAufGaesteliste` |
| `!` | Nicht: Wahrheitswert umkehren | `!hatTicket` |

`hatTicket` und `stehtAufGaesteliste` sind hier `bool`-Variablen.

- `true && false` ergibt `false`.
- `true || false` und `true || true` ergeben `true`.
- `!true` ergibt `false`; `!false` ergibt `true`.

Note:
- Oder ist einschließlich: Auch beide wahr ist erlaubt. ! steht vor genau dem Wert oder geklammerten Ausdruck, den es umkehrt.
- && und || prüfen rechts nur, wenn es für das Ergebnis nötig ist. Keine Seiteneffekte in heutigen Bedingungen.
- Referenz: https://learn.microsoft.com/en-us/dotnet/csharp/language-reference/operators/boolean-logical-operators

---

## Zusammengesetzte Bedingungen

```csharp [4]
int alter = 20;
bool hatTicket = false;
bool stehtAufGaesteliste = true;
if ((alter >= 18) && (hatTicket || stehtAufGaesteliste))
{
    Console.WriteLine("Zutritt erlaubt");
}
else
{
    Console.WriteLine("Kein Zutritt");
}
```

`true && (false || true)` → `true && true` → `true`.

Die äußeren `(...)` gehören zu `if`; die inneren gruppieren Teilbedingungen.

Note:
- Die Markierung zeigt die zusammengesetzte Bedingung. Ausgabe hier: Zutritt erlaubt. Danach fragen: Welche Änderung führt zum else-Block?
- Zuerst die Klammern auswerten. Ohne Klammern bindet ! stärker als &&, && stärker als ||. Zur Lesbarkeit Bereiche ausdrücklich klammern.
- alter >= 18 && <= 65 ist kein gültiges C#: Jeden Vergleich vollständig schreiben, etwa (alter >= 18) && (alter <= 65).

## Zusammenfassung

- Ein Programm verarbeitet Anweisungen und Werte.
- Eine Variable hat einen **Typ**, einen **Namen** und einen **aktuellen Wert**.

- switch wählt anhand eines Werts einen passenden Fall. Hier wird Gut ausgegeben.
- case beschreibt einen festen Vergleichswert, default den Fall ohne passende Zuordnung.
- break beendet hier den switch-Block; danach geht das Programm weiter.
- Moderne Varianten und Pattern Matching heute auslassen.

---

## Aufgabe 10: Taschenrechner

*Optionale Vertiefung*

**Ziel:** Mit `switch` zwischen festen Rechenoperationen wählen.

**Anforderungen:**

1. Lesen Sie eine Zahl, einen Operator als Text und eine zweite Zahl ein. Verwenden Sie `double` für die Zahlen.
2. Berechnen Sie mit `switch` das Ergebnis für `"+"`, `"-"`, `"*"` oder `"/"` und geben Sie es aus.
3. Melden Sie im `default`-Fall einen unbekannten Operator.

**Tipps:** Ein Fall beginnt mit `case "+":` und endet hier mit `break;`. Testen Sie zunächst gültige Zahlen und bei Division einen Divisor ungleich 0.

Note:
- Optional. Alle vier Operationen und einen unbekannten Operator testen. Aufgabe 13 ergänzt die Prüfung auf null.

## Aufgabe 11: Noten in Text umwandeln

*Optionale Vertiefung*

**Ziel:** Feste Werte mit `switch` zuordnen.

**Anforderungen:**

1. Lesen Sie eine Schulnote als ganze Zahl ein.
2. Ordnen Sie zu: 1 → Sehr gut; 2 → Gut; 3 → Befriedigend; 4 → Ausreichend; 5 → Mangelhaft; 6 → Ungenügend.
3. Geben Sie für andere Zahlen `Ungültige Note` aus.

**Tipps:** Beginnen Sie mit zwei `case`-Fällen. Ergänzen Sie die übrigen und `default`. Testen Sie auch `0` und `7`.

Note:
- Optional. break beendet den switch, nicht das gesamte Programm.

## Aufgabe 12: Schaltjahr-Rechner

*Optionale Vertiefung*

**Ziel:** Mehrere Teilbedingungen zu einer Entscheidung verbinden.

**Anforderungen:**

1. Lesen Sie eine positive Jahreszahl ein.
2. Ein Jahr ist ein Schaltjahr, wenn es durch 4, aber nicht durch 100 teilbar ist, oder wenn es durch 400 teilbar ist.
3. Geben Sie aus, ob das Jahr ein Schaltjahr ist.

**Tipps:** Verwenden Sie `%`, `==`, `!=`, `&&`, `||` und Klammern. Testfälle: 2000 und 2024 → ja; 1900 und 2023 → nein.

Note:
- Optional. Gregorianische Regel als Rechenübung. Teilbedingungen zuerst einzeln formulieren.

## Aufgabe 13: Division durch null abfangen

*Optionale Vertiefung*

**Ziel:** Eine bestehende Entscheidung um einen Sonderfall erweitern.

**Anforderungen:**

1. Erweitern Sie den Taschenrechner aus Aufgabe 10.
2. Prüfen Sie im Divisionsfall die zweite Zahl: Bei `0` geben Sie eine verständliche Meldung aus und führen die Division nicht aus.
3. Andernfalls berechnen Sie das Ergebnis wie bisher.

**Tipps:** Verwenden Sie `if`/`else` im passenden `case`-Block. Testen Sie `10 / 2` und `10 / 0`.

Note:
- Optional. double-Division durch null kann Infinity oder NaN ergeben. Die fachliche Regel soll dies hier verhindern.

## Aufgabe 14: Login-Simulation

*Optionale Vertiefung*

**Ziel:** Textvergleiche und verschachtelte Entscheidungen anwenden.

**Anforderungen:**

1. Legen Sie `korrekterName = "admin"` und `korrektesPasswort = "uebung"` als `string`-Variablen an.
2. Lesen Sie einen Namen und ein Passwort ein.
3. Geben Sie aus: Name falsch → `Benutzername nicht gefunden.`; nur Passwort falsch → `Falsches Passwort.`; beide richtig → `Login erfolgreich!`.

**Tipps:** Vergleichen Sie mit `==`. Prüfen Sie das Passwort innerhalb des passenden Namensfalls mit einer weiteren `if`/`else`-Anweisung. Testen Sie alle drei Fälle.

Note:
- Optional. Reine Ablaufübung, kein Vorbild für ein echtes Login. == berücksichtigt bei diesen Textvergleichen die Groß-/Kleinschreibung.
